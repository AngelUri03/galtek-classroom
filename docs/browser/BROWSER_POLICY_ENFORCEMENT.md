# Browser Policy Enforcement

Prompt 16D implements Agent-side enforcement of Galtek browser navigation policy for Google Chrome and Microsoft Edge on Windows.

## Native Mechanism

Galtek uses the supported Chromium enterprise policies:

- Chrome `URLBlocklist`
- Chrome `URLAllowlist`
- Edge `URLBlocklist`
- Edge `URLAllowlist`

The Agent writes policy values for the real interactive Windows user under:

```text
HKEY_USERS\<REAL_USER_SID>\Software\Policies\Google\Chrome\URLBlocklist
HKEY_USERS\<REAL_USER_SID>\Software\Policies\Google\Chrome\URLAllowlist
HKEY_USERS\<REAL_USER_SID>\Software\Policies\Microsoft\Edge\URLBlocklist
HKEY_USERS\<REAL_USER_SID>\Software\Policies\Microsoft\Edge\URLAllowlist
```

Galtek does not write HKLM for classroom browser navigation policy, because HKLM would affect every Windows account on the machine and could conflict with administrator, GPO, MDM or school policy.

## Registry Format

Each list uses sequential `REG_SZ` value names generated by the Agent:

```text
1 = "youtube.com"
2 = ".school.example"
```

The Master never sends registry paths, value names, raw policy names, commands, scripts or shell arguments. It sends only typed Galtek policy semantics.

Each native list is limited to 1000 filters after canonicalization and dedupe. If the compiled policy exceeds that limit, the Agent returns `BROWSER_POLICY_TOO_LARGE` and does not truncate.

## Compilation

Galtek compiles policy rules conservatively:

- `HOST_EXACT example.com` -> `.example.com`
- `HOST_SUFFIX example.com` -> `example.com`
- `HOST_EXACT 192.168.1.10` -> `192.168.1.10`
- `URL_PREFIX https://example.com/material/` -> `https://.example.com/material/`
- non-default ports are preserved
- default ports are normalized away

`EXACT_URL` is not compiled in 16D. Chromium native URL policies do not provide a safe general byte-for-byte equivalent for Galtek `EXACT_URL`, so an active policy containing it returns `BROWSER_POLICY_NOT_NATIVE_ENFORCEABLE`.

Mode compilation:

- `UNRESTRICTED`: empty block/allow filters, removing only Galtek-owned policy.
- `BLOCKLIST`: enabled `BLOCK` rules become block filters and enabled `ALLOW` rules become allow filters.
- `ALLOWLIST`: block filter `*` plus enabled `BLOCK` rules, with enabled `ALLOW` rules in allow filters.

The Agent canonicalizes, dedupes and sorts deterministically, then hashes the canonical representation for idempotence.

## Matching Semantics

Galtek now follows the supported Chromium subset:

1. most specific host wins;
2. then compatible scheme/port specificity;
3. then longer path prefix;
4. then more specific query;
5. only at equal specificity, `ALLOW` wins over `BLOCK`.

This replaces the older 16C simplification that `ALLOW` always won over `BLOCK`.

## Ownership

Galtek stores local durable state in:

```text
browser-navigation-policy-state.json
```

It also writes a short apply journal:

```text
browser-navigation-policy-apply.json
```

Before first apply, if any target HKU subkey already contains unknown values, Galtek returns `BROWSER_POLICY_EXTERNAL_CONFLICT`. It also fails conflict if relevant HKLM machine-level Chrome/Edge policies exist.

Before updating an already Galtek-owned policy, the Agent compares real registry values to the last durable state. If they diverge, Galtek does not overwrite silently and returns `BROWSER_POLICY_EXTERNAL_CONFLICT`.

## ACL

For Galtek-owned subkeys:

- LocalSystem: FullControl
- Builtin Administrators: FullControl
- target user: ReadKey

The target user can read the policies so Chrome/Edge can consume them, but must not receive write rights. Galtek does not grant writer rights to Everyone, Authenticated Users or Builtin Users.

## Durability And Recovery

`SUCCESS` for `APPLY_BROWSER_NAVIGATION_POLICY` means:

1. registry values were written;
2. registry values were read back and verified;
3. local durable state was written.

It does not mean Chrome/Edge was installed, open, restarted, or that every existing tab immediately changed state.

On the next apply, lazy recovery handles any previous journal:

- registry equals desired: finalize durable state and clear journal;
- registry equals previous: clear journal;
- registry is intermediate but only contains known Galtek values: restore previous;
- registry has unknown divergence: return `BROWSER_POLICY_RECOVERY_REQUIRED`.

There is no timer, polling, process scan, browser scan or registry polling.

## OPEN_URL Defense In Depth

`OPEN_URL` still runs structural URL safety first. After that, the Agent checks the locally applied Galtek browser policy for the current interactive user. If the policy blocks the URL, the Agent does not send a Session Command and returns `URL_BLOCKED_BY_POLICY`.

If no Galtek policy is applied locally, `OPEN_URL` keeps the 16B behavior and relies only on structural URL safety.

## Limits

URLBlocklist/URLAllowlist control browser URL navigation and URL loads. They are not a firewall, proxy, DNS filter, DLP system, HTTPS inspector or packet filter.

A page already loaded may perform dynamic behavior that is not equivalent to a fresh browser navigation. Galtek does not promise complete traffic inspection.

16D does not implement downloads policy, browser profiles, Chrome/Edge extensions, proxy/DNS/firewall/hosts enforcement, browser automation, tab monitoring, history monitoring, process monitoring, PRIMARY/SECONDARY SID binding, login/logoff, UI or Master batch dispatch.

`accountScope = ANY` applies to the current interactive user. `PRIMARY` and `SECONDARY` return `BROWSER_ACCOUNT_SCOPE_UNRESOLVED` until managed Windows account SID binding exists.
